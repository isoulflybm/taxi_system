# Геокодирование, маршруты и заказ поездки

## Локальные геосервисы Кыргызстана

Веб-приложение обращается к Nominatim через `NOMINATIM_BASE_URL`, а к OSRM — через `OSRM_BASE_URL`. Вариант `docker-compose.geo.yml` поднимает собственные экземпляры обоих сервисов по региональному файлу OSM; координаты водителей и адресные запросы не отправляются в публичный Nominatim.

Эти контейнеры обеспечивают поиск адресов и прокладку маршрутов. Визуальный стиль MapLibre пока продолжает загружаться из OpenFreeMap; собственный сервер векторных тайлов Кыргызстана в эту конфигурацию не включён.

1. Поместите ранее скачанный файл `kyrgyzstan-261031.osm.pbf` в каталог `data/` проекта.
2. Убедитесь, что в `.env` заданы `NOMINATIM_PASSWORD`, `NOMINATIM_USER_AGENT`, `OSM_DATA_DIR=./data` и `OSM_PBF_FILE=kyrgyzstan-261031.osm.pbf`.
3. Запустите сервисы с профилем геоданных:

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.dev.yml -f docker-compose.geo.yml --profile geodata up -d --build
   ```

4. Первый запуск импортирует региональный PBF и построит граф дорожной сети. Это длительная и ресурсоёмкая операция; не удаляйте тома `nominatim_data`, `nominatim_flatnode` и файлы `data/*.osrm*` после импорта. Посмотреть прогресс можно командой:

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.dev.yml -f docker-compose.geo.yml --profile geodata logs -f nominatim osrm
   ```

   Чтобы повторно начать импорт с нуля, сначала остановите геосервисы и удалите их тома/производные OSRM-файлы осознанно.

Адрес ищется по запросу пользователя, только в Кыргызстане, с кэшированием. Автодополнение не используется. Контейнер Nominatim сохраняет импортированную базу между перезапусками. Поддержка ежедневных обновлений карт требует отдельной задачи обслуживания и контроля успешного применения репликаций.

## API

- `GET /api/geo/search/?q=...` — поиск адреса (доступен гостю и клиенту).
- `GET /api/geo/route/?start_lon=...&start_lat=...&end_lon=...&end_lat=...` — длина, длительность и геометрия маршрута, предварительная цена по активному тарифу.
- `GET /api/geo/nearby-drivers/?lat=...&lon=...` — число свободных водителей с актуальной геолокацией и активным автомобилем. Точные координаты водителей гостям не выдаются.
- `POST /api/orders/` — клиент создаёт заказ. Сервер сам строит маршрут, сохраняет тарифный снимок и пытается назначить ближайшего свободного водителя.
- `POST /api/orders/{id}/driver-arriving/`, `/start/`, `/complete/`, `/decline/`, `/cancel/` — смена статуса поездки, отказ водителя с передачей заказа следующему или отмена клиентом/диспетчером.
- `POST /api/orders/{id}/retry_assignment/` — диспетчер повторяет поиск водителя для заказа без назначения.
- `POST /api/orders/{id}/payments/record/` — диспетчер фиксирует подтверждённую оплату; комиссия и доля водителя сохраняются снимком в платёжной записи.

## Регистрация и тариф

`/accounts/signup/` позволяет создать профиль клиента или водителя. Водитель появляется в поиске только после того, как администратор добавит ему активный автомобиль; он также должен передавать свежую геолокацию. Веб-страница `/driver/location/` остаётся открытой во время смены и подходит для первого теста, но не передаёт координаты в фоне после закрытия браузера.

Перед первым заказом администратору нужно создать в Django Admin активный тариф без зоны, указав реальные цены подачи, километра, минуты и минимальную стоимость. Суммы намеренно не зашиты в код.

Предварительная стоимость считается по маршруту OSRM: базовая цена + километры + минуты с ограничением минимальной стоимостью. Тариф и его ставки сохраняются в заказе, чтобы дальнейшее изменение тарифа не меняло уже созданный заказ. При завершении поездки цена пересчитывается по GPS-точкам поездки; при недостатке точек используется дорожная оценка.

## Комиссия и платежи

В Django Admin появится раздел «Настройки комиссии». Установите там процент комиссии сервиса. Для каждой подтверждённой платёжной записи сохраняются применённый процент, сумма комиссии и сумма водителю.

Это учётная основа комиссии, а не подключение эквайринга: для реального приёма карт нужны выбранный платёжный провайдер, его учётные данные, безопасный webhook и сценарии возврата/сверки. Сейчас подтверждённую оплату фиксирует диспетчер через API или админку.

Роль «диспетчер» сама по себе не получает процент с заказа. Комиссия в настройках принадлежит сервису Taxi KG. Вознаграждение диспетчера — отдельное решение компании: обычно это зарплата/оплата смены или отдельный бонус, если вы хотите его ввести. Не смешивайте его с удержанием сервиса; отдельную формулу бонуса диспетчеру пока не закладывали.
