# Развёртывание Taxi KG

## 1. Что понадобится

- Docker Engine и Docker Compose plugin;
- Git — если исходники будут получены из репозитория;
- для публичного запуска — Ubuntu 24.04, домен и DNS A/AAAA-записи на сервер.

## 2. Локальный запуск для разработки

Из каталога `taxi-kg`:

```bash
cp .env.example .env
```

Откройте `.env` и задайте локальный `DJANGO_SECRET_KEY` и пароль базы. Затем запустите сервисы:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

После первого запуска миграции применятся автоматически. Создай администратора:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml exec web python manage.py createsuperuser
```

Откройте:

- API health check: http://127.0.0.1:8000/health/
- Django admin: http://127.0.0.1:8000/admin/
- PostGIS с хоста: `127.0.0.1:5433`.

Остановка: `Ctrl+C`, затем:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml down
```

Данные PostgreSQL остаются в Docker volume. Команда `down -v` удалит их.

## 3. Публичное развёртывание на Ubuntu 24.04

### Подготовка сервера

1. Установите Docker Engine и Compose plugin по официальной инструкции Docker для Ubuntu.
2. Направьте домен на сервер и разрешите входящие TCP-порты 80 и 443 в firewall. SSH оставьте доступным для администрирования.
3. Получите проект на сервере через `git clone` или распакуйте архив и перейдите в каталог `taxi-kg`.
4. Создайте рабочий файл окружения:

   ```bash
   cp .env.example .env
   nano .env
   ```

5. В `.env` задайте `DOMAIN=ваш-домен.example`, `DJANGO_ALLOWED_HOSTS=ваш-домен.example`, `CSRF_TRUSTED_ORIGINS=https://ваш-домен.example`, `DJANGO_DEBUG=0`, новый длинный `DJANGO_SECRET_KEY` и уникальный `POSTGRES_PASSWORD`. По умолчанию диспетчерская использует стиль OpenFreeMap на данных OpenStreetMap; свой стиль можно указать через `MAP_STYLE_URL`, а совместимый адресный поиск — через `NOMINATIM_BASE_URL`.
6. Не используйте значения из `.env.example` на публичном сервере и не добавляйте `.env` в Git.

### Запуск

Из каталога проекта выполните:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

При первом запуске приложение применит миграции и соберёт статические файлы. Caddy получит HTTPS-сертификат для домена, если DNS уже указывает на сервер и порты 80/443 доступны.

Перед публичным запуском убедитесь, что миграции из `apps/*/migrations/` попали на сервер. Затем создайте администратора:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec web python manage.py createsuperuser
```

Проверьте `https://ваш-домен.example/health/` и `https://ваш-домен.example/admin/`.

### Обслуживание

```bash
# Состояние и журналы
docker compose -f docker-compose.yml -f docker-compose.prod.yml ps
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs -f web caddy

# Обновление после получения новых исходников
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

До реальных поездок добавьте регулярный `pg_dump` в защищённое хранилище и проверьте восстановление backup. Не открывайте PostgreSQL, Redis или порт Django напрямую в интернет. Также настройте мониторинг диска и логов, а для координат — политику хранения и удаления.

## 4. Что уже подключено

- Django Admin для пользователей, профилей, машин, тарифов, зон, заказов и поездок.
- API заказов `/api/orders/`.
- Диспетчерская карта `/dispatch/map/` и снимок данных `GET /api/dispatch/map/`.
- Страница передачи геолокации водителя `/driver/location/` и приём `POST /api/tracking/location/`.
- Токенная авторизация GPS-клиентов через DRF Token Authentication.
- Поиск адреса на карте `GET /api/geo/search/?q=...` через настроенный Nominatim-совместимый сервис.
- WebSocket `/ws/dispatch/locations/` для доставки свежих координат диспетчерам.

## 5. Первые API-запросы

API списка заказов: `GET /api/orders/`. Создание заказа требует авторизации и принимает координаты в WGS84:

```json
{
  "pickup_latitude": 42.8746,
  "pickup_longitude": 74.5698,
  "dropoff_latitude": 42.8600,
  "dropoff_longitude": 74.6050,
  "pickup_address": "Точка подачи",
  "dropoff_address": "Точка назначения"
}
```

Пока заказ создаётся без цены и назначения водителя: цена должна рассчитываться по расстоянию и времени, полученным от маршрутизатора, а не из координатной прямой.

## Экран диспетчера и геолокация водителя

1. В Django Admin → «Пользователи» → «Добавить пользователя» создай водителя и выбери роль «Водитель». Аналогично создай диспетчера с ролью «Диспетчер». Телефон вводится там же.
2. Войди водителем через `/accounts/login/`, открой `/driver/location/` и разреши браузеру доступ к геолокации. Нужен HTTPS, кроме локального `localhost`; страницу оставь открытой.
3. В другом браузере войди диспетчером и открой `/dispatch/map/`. Начальные данные приходят через `GET /api/dispatch/map/`, новые координаты — через WebSocket `/ws/dispatch/locations/`.
4. Карта сразу показывает OpenFreeMap на данных OpenStreetMap. Для своего стиля задай `MAP_STYLE_URL`.

### Проверка с телефона

Можно использовать телефон без отдельного приложения: открой сайт Taxi KG в мобильном браузере, войди учётной записью с ролью «Водитель», перейди на `/driver/location/` и нажми «Начать передачу». Для браузерной геолокации нужен HTTPS (или адрес `localhost` на самом устройстве). `127.0.0.1` на телефоне указывает на сам телефон, а не на компьютер с Docker; для проверки используй HTTPS-домен тестового сервера либо временный HTTPS-туннель. Оставь страницу открытой: мобильная ОС может приостановить геолокацию в фоне.

### Токен для мобильного GPS-клиента

Для приложения, которое умеет отправлять JSON на произвольный HTTPS URL, создай токен для пользователя-водителя:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml exec web python manage.py drf_create_token driver2
```

Отправляй `POST https://ваш-домен/api/tracking/location/` с заголовками `Authorization: Token <полученный-токен>` и `Content-Type: application/json`. Пример тела:

```json
{
  "latitude": 42.8746,
  "longitude": 74.5698,
  "accuracy_m": 8.5,
  "heading": 120,
  "speed_mps": 6.2,
  "recorded_at": "2026-10-31T12:00:00Z"
}
```

Токен привязан к пользователю; API принимает координаты только у пользователя с ролью «Водитель». Храни токен как пароль и передавай только по HTTPS. При утрате создай новый токен с `drf_create_token --rotate driver2`.

### Аппаратный GPS-трекер

У автомобильного трекера обычно есть SIM-карта и собственный TCP/UDP-протокол производителя. Такой прибор не отправляет JSON в Django напрямую. Типовая схема: трекер → сервер-шлюз протоколов (например, Traccar) → адаптер/вебхук → API Taxi KG. Для первого теста проще телефон: браузерная страница выше или приложение-трекер, в котором настраиваются произвольный HTTP(S) URL, JSON и заголовок авторизации. Не всякое приложение-трекер поддерживает такой режим.

### Поиск адресов

Поиск вручную включается переменной `NOMINATIM_BASE_URL`, например URL собственного сервера Nominatim. Если переменная пустая, поле поиска скрыто. Запросы ограничены Кыргызстаном, кэшируются на 6 часов, а повторный запрос к геокодеру ограничен одним в секунду на весь экземпляр приложения. Не подключай публичный `nominatim.openstreetmap.org` к рабочему такси-сервису: его политика исключает приложения, основной функцией которых является отслеживание автомобилей/поставок, и запрещает автодополнение. Подними свой Nominatim или выбери поставщика с подходящими условиями. Укажите настоящий контакт в `NOMINATIM_USER_AGENT` для своего сервера/поставщика.

В этой среде стандартный `tile.openstreetmap.org` отвечает `403`, поэтому для подложки выбран OpenFreeMap — публичный сервис векторных тайлов на данных OpenStreetMap без ключа. Он подходит для прототипа, но предоставляется без SLA; для рабочего сервиса заложи собственный сервер тайлов или провайдера с SLA. MapLibre показывает атрибуцию источников карты автоматически.

Координаты сохраняются в PostGIS и сейчас остаются в базе без автоматического срока удаления. Перед реальной эксплуатацией настрой срок хранения и очистку истории. Приём ограничен 30 обновлениями в минуту на пользователя.

## Создание пользователя и выбор роли

Создавай водителей и диспетчеров через Django Admin → «Пользователи» → «Добавить пользователя». В этой форме теперь есть поля «Роль в Taxi KG» и «Телефон». Выбери нужную роль и введи телефон до сохранения. Профиль создаётся автоматически; раздела для ручного добавления профиля нет.

Для уже существующего аккаунта открой его в разделе «Пользователи» и измени роль и телефон в блоке «Профиль Taxi KG». Группы Django для назначения этих ролей не используются.
